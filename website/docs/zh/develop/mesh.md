# Mesh 与遇锁自愈

本页记录已发布的 HTTP Mesh 配置。开发版采用 WebRTC，需要全组切换。新版的信令、TURN、项目导出、Room 和迁移步骤见[配置与迁移](https://github.com/dsh-plugins/dsh-prism/blob/main/docs/CONFIG.md)。

棱镜在分布式执行层遵循两条核心路线：**位置透明的跨机抽象**（`dsh-mesh-node`）与**外轻内重、遇锁自愈的会话模型**，让编排逻辑无需感知网络拓扑，也不会被底层写锁卡死。

## 位置透明：把远程节点封装为标准 Provider

每个节点都通过统一的 `prism-<nodeId>` Subagent Provider 对外提供服务。对上层编排器而言，跨机派发与本地拉起子任务共用同一套接口契约：

1. 协调端签发一次性派发凭据并调用 `prism-<nodeId>`，目标节点返回其上正式 DSH 会话的 ID。
2. 结合「**L1 指定 L2 工作区、L3 强制继承 L2 工作区**」的规则，所有高频文件读写与检索都收敛在持有项目目录的目标机本地，跨网只传输轻量级控制信令、进度和摘要。
3. 请求到达工作节点后，工作节点仍会依据本地注册表与安全策略，独立复核调用方身份、项目授权、模型及工具上限。

## 连接两个节点

将第一段 `mesh` 配置放在协调端（`hub`），第二段放在执行端（`worker`）。两端通过 `PRISM_WORKER_TOKEN` 共享同一个随机链路令牌，并在双方注册表中都登记项目 `atlas`（`nodeId` 设为 `worker`），物理路径仅在 `worker` 端解析。

**协调端（`hub`）**：

```json
{
  "nodeId": "hub",
  "peers": [{ "id": "worker", "url": "https://worker.example.org", "tokenEnv": "PRISM_WORKER_TOKEN" }]
}
```

**执行端（`worker`）**：

```json
{
  "nodeId": "worker",
  "incoming": [{ "id": "hub", "tokenEnv": "PRISM_WORKER_TOKEN", "projects": ["atlas"] }]
}
```

跨设备通信请使用 HTTPS，并将工作节点域名加入 DSH 可信主机列表（本机测试允许使用回环 HTTP）。每台设备各自维护独立的 `DSH_HOME`，两端无需共享 SQLite 或项目文件系统；协调端主动发起出站连接，并通过该链路接收工具回调。

## 外轻内重与遇锁自愈（Copy-on-Conflict）

各层在接口上保持 Subagent 的轻量与简洁，但在存储与运行层**全部落为正式的 DSH 会话**，从而天然具备持久化、断点续跑与原生只读检视能力。

为了防止会话写锁阻塞编排流程，棱镜将「逻辑智能体身份」与「物理会话实例」解耦：

1. 启用已绑定会话时，若检测到 DSH 写锁冲突，运行器既不死等，也不强行抢锁。
2. 运行器会立即从原会话的可观测历史 **Fork** 出一个新的物理 DSH 会话。
3. 随后以原子方式将逻辑身份重新绑定到新会话，并记录原会话的归档义务（多个发布者竞争时，会重新校验最终生效的绑定）。

## 持久化与远程只读检视

- **双层持久化**：用户消息、模型选择、任务状态与待投递的 Actor 信令存储在 `conversations.sqlite`，完整执行轨迹由 DSH 原生会话日志保存。重启时请保留协调端与工作端的状态目录。
- **故障恢复**：重启后，尚未开始的已提交轮次会自动继续；运行中途失去执行者的任务会被标记为失败，便于操作者先核查现场副作用再决定是否重试。
- **无锁远程 Trace**：已授权的只读查询通过同一条 Mesh 链路读取工作节点的会话记录，全程不获取写锁。若网络中断发生在可能产生副作用的操作期间，请先查看任务轨迹再决定是否重发。
