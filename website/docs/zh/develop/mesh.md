# Mesh 与遇锁自愈

`dsh-mesh-node` 0.2.1 通过加密的 WebRTC DataChannel 连接互相信任的设备。WSS 信令服务转发连接协商消息，任务、项目索引、进度和 Room 消息通过设备之间的数据通道传输。需要中继时，TURN 转发加密数据。

编排器使用同一个 DSH 子代理提供方接口派发本地及远程任务。文件操作在项目所在设备执行。

## 位置透明：把远程节点封装为标准 Provider

编排器为各节点注册名为 `prism-<nodeId>` 的子代理提供方。

1. L1 可用 `agent_spawn` 一次向多个节点派发 L2 任务，以 `(nodeId, projectId)` 指定各任务的项目。目标节点创建或恢复 DSH 原生会话。
2. L3 继承 L2 的工作区。执行节点根据本地配置复核对端的项目导出授权、用户权限、模型、工具权限与委派深度。
3. 派发时可选 `room: true`。本批获准的 L2 任务可用 `peer_send` 互发消息，参与设备需互相登记公钥。接收任务从持久化收件箱读取消息。

## 连接两个节点

支持托管连接的版本可在 **设置 → 棱镜/连接** 使用同一个信令地址和同一个随机连接码。两端点击 **连接** 即可配对。需要在本机提供网络服务时，在「作为服务端」下启用信令或 STUN/TURN。中继凭据在连接页单独填写。配对后的项目导出及 NAT 转发要求见[配置与迁移](https://github.com/dsh-plugins/dsh-prism/blob/main/docs/CONFIG.md#在设置中配对)。

### 静态节点

1. 为每台设备设置唯一的 `nodeId` 和独立的 Ed25519 密钥。在信令服务和对端的 `peers[].publicKey` 中登记设备公钥。
2. 两端用 `webrtc.signalingUrl` 连接同一个可访问的 `wss://` 信令地址。将各自的 PKCS#8 PEM 私钥写入 `webrtc.privateKeyEnv` 指定的环境变量，按网络条件配置 `webrtc.iceServers` 中的 STUN 或 TURN。
3. 在执行端登记 `atlas` 项目的本地绝对路径与权限，并将 `atlas` 加到执行端上协调设备对应的 `peers[].projects`。协调端通过 Mesh 发现获准项目的元数据。

每台设备使用独立的 DSH 配置档。完整配置和旧 Mesh 的分组升级步骤见[配置与迁移](https://github.com/dsh-plugins/dsh-prism/blob/main/docs/CONFIG.md)。

## 外轻内重与遇锁自愈（Copy-on-Conflict）

各层在 DSH 原生会话中运行。符合条件的本机会话会在对应工作区发布独立的只读历史。

为了防止会话写锁阻塞编排流程，棱镜将「逻辑智能体身份」与「物理会话实例」解耦：

1. 启用已绑定会话时，若检测到 DSH 写锁冲突，运行器既不死等，也不强行抢锁。
2. 运行器会立即从原会话的可观测历史 **Fork** 出一个新的物理 DSH 会话。
3. 运行器将逻辑身份原子地绑定到新会话。发布只读历史无需获取正在运行的会话写锁。

## 持久化与远程只读检视

- **双层持久化**：用户消息、模型选择、任务状态与待投递的 Actor 信令存储在 `conversations.sqlite`，完整执行轨迹由 DSH 原生会话日志保存。重启时请保留协调端与工作端的状态目录。
- **故障恢复**：重启后，尚未开始的已提交轮次会自动继续；运行中途失去执行者的任务会被标记为失败，便于操作者先核查现场副作用再决定是否重试。
- **远程会话历史**：协调端显示任务状态和结果。完整记录可在执行设备的 DSH 工作区查看。遇到网络中断时，应先核对可能已经完成的操作，再决定是否重试。
