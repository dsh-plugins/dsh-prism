# Роли и права

Каждая роль работает в полноценном сеансе DSH и доступна через Subagent Provider. Хост проверяет права при перечислении и при вызове инструментов.

| Роль | Назначение и границы прав |
| --- | --- |
| **L1** | Общается с пользователем в проекте по умолчанию, запрашивает разрешённые метаданные и выбирает проект и модель L2. Инструменты файловой системы и терминала недоступны. |
| **L2** | Планирует в выбранном L1 проекте, подбирает модели L3, распределяет шаги и может сужать их права. Обменивается сообщениями с непосредственным родителем и потомками. |
| **L3** | Выполняет шаг на узле и в рабочем каталоге родителя. Нативные инструменты ограничены ролью, политикой проекта и переданными правами. |

## Сообщения и завершение

L1 публикует ответ пользователю через `send_user`. Обычный текст модели сохраняется в сеансе. `send_parent` и `send_child` активируют получателя через очередь. Родитель может запросить `get_progress`. При завершении задачи он получает событие `task_settled`.

| Роль | Инструменты координации |
| --- | --- |
| L1 | `query_projects`, `list_models`, `dispatch_planner`, `send_child`, `get_progress`, `send_user` |
| L2 | `list_models`, `dispatch_executor`, `send_parent`, `send_child`, `get_progress`, `report_progress` |
| L3 | `send_parent`, `report_progress` |

Изменение карточки не требует нового ответа агента. После события L1 решает, стоит ли отправлять сообщение. `list_models` показывает возможности моделей следующего уровня.
