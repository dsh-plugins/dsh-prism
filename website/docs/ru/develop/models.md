# Модели и проекты

Prism разделяет **выбор модели** и **разрешение физического пути**, совмещая гибкую маршрутизацию во время выполнения со строгим контролем доступа на стороне доверенного хоста.

## Пулы моделей по уровням

В **Settings → Prism/Configuration** (или `orchestrator.models` в `prism.config.json`) уровни **L1**, **L2** и **L3** настраиваются независимо. Пустой уровень использует модель DSH по умолчанию.

- `id` и необязательный `provider`: задают модель и провайдера DSH.
- `description`: резюме возможностей, которое старший уровень читает через `list_models`.
- `prompt` и `promptMode`: `"append"` (по умолчанию) дополняет системный промпт роли; `"replace"` заменяет его целиком, не расширяя прав на инструменты.

Модель **L1** свободно выбирает пользователь, а **L2** и **L3** динамически подбирает вышестоящий агент.

Если модель используется на нескольких уровнях, задайте одно и то же описание и одну и ту же подсказку на каждом из них. Описание указывает возможности и подходящие сценарии применения, а подсказка задаёт общие предпочтения для модели. См. [описания и подсказки моделей](../guide/model-metadata.md).

```json
{
  "defaultProjectId": "prism",
  "defaultL1Model": "example-model",
  "models": {
    "L1": [{ "id": "example-model", "description": "Подходит для задач с чёткими границами.", "promptMode": "append", "prompt": "Пишите кратко и естественно." }],
    "L2": [{ "id": "example-model", "description": "Подходит для задач с чёткими границами.", "promptMode": "append", "prompt": "Пишите кратко и естественно." }],
    "L3": [{ "id": "example-model", "description": "Подходит для задач с чёткими границами.", "promptMode": "append", "prompt": "Пишите кратко и естественно." }]
  }
}
```

## Обнаружение и реестр проектов

1. **Автообнаружение DSH**: каждая папка, открытая на боковой панели, регистрируется по нативному UUID и отображаемому имени (по умолчанию `read`, `glob`, `grep` для владельца и одобренных пользователей IM).
2. **Явный реестр (`registry`)**: задаёт `id`, `description`, `stack`, `nodeId`, `workspace`, `principals`, `permissions` и необязательный `gitRemote` с приоритетом над автообнаружением.

`query_projects` передаёт в L1 только разрешённые метаданные; физические пути разрешаются исключительно в доверенном коде хоста.
