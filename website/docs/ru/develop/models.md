# Модели и проекты

Реестр описывает доступные проекты. Оркестратор отдельно задаёт модели и нативные инструменты для каждой роли.

## Модели по уровням

Поместите фрагмент в раздел `orchestrator` файла `prism.config.json`. Идентификаторы моделей должны поддерживаться активным провайдером и быть уникальными в пределах одного уровня.

```json
{
  "defaultProjectId": "prism",
  "defaultL1Model": "deepseek-flash",
  "models": {
    "L1": [{ "id": "deepseek-flash", "description": "Уточнение запроса пользователя" }],
    "L2": [{ "id": "deepseek-v4-pro", "description": "Планирование и проверка" }],
    "L3": [{ "id": "deepseek-flash", "description": "Целевой обзор кода", "promptMode": "append", "prompt": "Укажи проверенные файлы." }]
  }
}
```

## Описание и системная инструкция

`description` помогает родительскому агенту выбрать модель под задачу. `provider` задаёт провайдера DSH. Если параметр отсутствует, используется провайдер хоста по умолчанию.

`promptMode: "append"` дополняет системную инструкцию указаниями роли и модели. В режиме `"replace"` значение `prompt` становится полной пользовательской системной инструкцией. Права на инструменты всё равно проверяет хост.

## Доступ к проектам

Запись содержит `id`, `description`, `stack`, `nodeId`, `workspace`, `principals`, `permissions` и необязательный `gitRemote`. L1 получает разрешённые метаданные. Только доверенный код хоста раскрывает физический каталог. Для L3 действует пересечение набора инструментов, политики проекта и делегированных родителем прав.
