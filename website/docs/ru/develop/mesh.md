# Mesh и сеансы

Prism 0.2.0 соединяет доверенные устройства через зашифрованные каналы WebRTC. Служба сигнализации WSS помогает установить соединение. При необходимости TURN пересылает зашифрованные данные.

## Прозрачность расположения

Координатор использует провайдер DSH Subagent Provider `prism-<nodeId>` для каждого узла. L1 может запустить несколько задач L2 одним вызовом `agent_spawn` и задать проекты через `(nodeId, projectId)`. L3 наследует рабочую область L2. При `room: true` задачи L2 в одной группе с соответствующими правами могут обмениваться сообщениями через `peer_send`.

## Подключение двух узлов

Укажите для каждого устройства отдельные `nodeId`, профиль DSH и ключ Ed25519. Зарегистрируйте открытые ключи в службе сигнализации и в `peers[].publicKey` на устройствах-партнёрах. Настройте `webrtc.signalingUrl`, `webrtc.privateKeyEnv` и при необходимости добавьте STUN или TURN в `webrtc.iceServers`. Открывайте доступ к проектам с узла исполнения через `peers[].projects`. Примеры и порядок совместного обновления приводятся в разделе [Настройка и миграция](https://github.com/dsh-plugins/dsh-prism/blob/main/docs/CONFIG.md).

## Virtual Facade & Copy-on-Conflict

При конфликте блокировки записи исполнитель создаёт новый сеанс DSH на основе наблюдаемой истории и атомарно обновляет привязку. История для просмотра хранится в отдельном сеансе только для чтения.

## Надёжность и удалённый просмотр

Координатор показывает статусы и результаты задач. Полные журналы хранятся в сеансах DSH на устройстве исполнения. Для просмотра откройте рабочую область проекта на этом устройстве.
