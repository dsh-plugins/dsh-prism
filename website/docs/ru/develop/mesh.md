# Mesh и сеансы

Координатор направляет сеанс провайдеру `prism-<nodeId>`. Для локального и удалённого выполнения применяется один контракт.

## Подключение двух узлов

Первый блок `mesh` укажите на координаторе, второй — на исполнителе. Задайте один случайный секрет в `PRISM_WORKER_TOKEN` на обеих машинах. Зарегистрируйте `atlas` с узлом `worker` по обе стороны. Физический путь определяет исполнитель.

```json
{
  "nodeId": "hub",
  "peers": [{ "id": "worker", "url": "https://worker.example.org", "tokenEnv": "PRISM_WORKER_TOKEN" }]
}
```

```json
{
  "nodeId": "worker",
  "incoming": [{ "id": "hub", "tokenEnv": "PRISM_WORKER_TOKEN", "projects": ["atlas"] }]
}
```

Между устройствами используйте HTTPS и добавьте имя исполнителя в доверенные хосты DSH. Для локальных тестов допустим HTTP на loopback. У каждого узла свой `DSH_HOME`. Соединение открывает координатор; через него он получает вызовы инструментов.

## Активация и конфликт блокировок

Исполнитель повторно проверяет отправителя, проект, модель и права. При конфликте блокировки записи он создаёт ответвление из доступной истории, атомарно публикует новую привязку и регистрирует исходный сеанс для архивирования. Конкурирующие процессы повторно проверяют принятую привязку.

## Удалённый просмотр

Авторизованный запрос читает сеанс по тому же соединению без блокировки записи. Сохраняйте каталоги состояния обоих узлов при перезапусках. После обрыва соединения проверьте статус задачи перед повтором операции с побочными эффектами.
