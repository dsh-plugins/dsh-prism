# Мессенджеры

Аутентифицированный личный чат привязывается к постоянной идентичности L1. Каждый канал независимо от браузера получает явные ответы и обновления задач.

## Настройка через интерфейс DSH

Откройте настройки Prism и выберите один из семи сервисов в разделе **Messaging channels**. Здесь можно управлять учётными данными, разрешёнными пользователями, кодами сопряжения и состоянием подключения. Для Feishu/Lark доступна регистрация по QR-коду. В русской версии DSH этот раздел показывает английские подписи. [Руководство со снимками на английском](/guide/im) · [Руководство со снимками на китайском](/zh/guide/im)

## Вход и сопряжение при запуске из исходного кода

Включите адаптер в разделе `im` файла `prism.config.json`. Для входа по QR запустите команду на координаторе и отсканируйте код соответствующим приложением. Для нового пользователя создайте код на хосте и попросите отправить `/pair CODE` боту в личном чате.

Команды ниже — варианты для разных каналов. Выполните нужную в `runtime/`. `setup` включает адаптер и перечисляет переменные окружения. Для каналов без QR также создаётся первый код сопряжения; для следующего пользователя используйте `pair`.

```sh
npm run im -- login wechat --config prism.config.json
npm run im -- login feishu --config prism.config.json
npm run im -- setup telegram --config prism.config.json
npm run im -- pair telegram --config prism.config.json
```

После проверки QR учётные данные сохраняются локально, а выполнивший сканирование пользователь получает доступ. Код сопряжения действует один раз в течение десяти минут. Для своего каталога состояния передайте CLI `--config prism.config.json` и запускайте координатор с тем же файлом.

## Поддерживаемые подключения

| Платформа | Подключение |
| --- | --- |
| Telegram | Длинный опрос Bot API. Укажите токен через `im.telegram.tokenEnv`, разрешите пользователя или выполните сопряжение и удалите прежний webhook. |
| WeChat | Личный WeChat через iLink. Выполните `login wechat` на хосте и откройте личный чат проверенной учётной записи. |
| Feishu / Lark | Авторизуйте приложение через `login feishu`. Настройте разрешения приложения и обмен сообщениями на платформе. |
| WeCom | Укажите корпоративного бота и учётные данные в `im.wecom`, затем выполните сопряжение в личном чате. |
| OneBot | Подключите OneBot для личных сообщений и направьте подписанные события в `/prism/im/onebot`. |
| QQ | Укажите официальный callback QQ `/prism/im/qq`. Шлюз проверяет подпись платформы. |
| Discord | Разрешите боту Discord принимать личные сообщения и выполните сопряжение в DM. |

## Ключи конфигурации для запуска из исходного кода

Включайте только нужные каналы и задавайте секреты в окружении координатора. `allowedUserIds` разрешает известные идентификаторы пользователей платформы. Сохраняйте SQLite при перезапуске, чтобы сохранить данные QR-входа и сопряжений.

| Платформа | JSON | ENV |
| --- | --- | --- |
| Telegram | `im.telegram.tokenEnv` | `TELEGRAM_BOT_TOKEN` |
| WeChat | `im.wechat` | — |
| Feishu / Lark | `im.feishu.domain`, `appId`, `appSecretEnv` | `FEISHU_APP_SECRET` |
| WeCom | `im.wecom.botId`, `secretEnv` | `WECOM_BOT_SECRET` |
| OneBot | `im.onebot.selfId`, `apiBase`, `accessTokenEnv`, `eventSecretEnv` | `ONEBOT_ACCESS_TOKEN`, `ONEBOT_EVENT_SECRET` |
| QQ | `im.qq.appId`, `appSecretEnv` | `QQ_BOT_SECRET` |
| Discord | `im.discord.tokenEnv` | `DISCORD_BOT_TOKEN` |

Если события не приходят, проверьте адрес callback или исходящее подключение канала. Для QQ C2C действуют ограничения платформы на срок ответа и инициативные сообщения. Если карточку нельзя отредактировать, некоторые каналы отправляют новое сообщение со статусом.

## Команды чата

| Интерфейс | Действие |
| --- | --- |
| `/models` | Список моделей L1 и их возможностей. |
| `/model …` | Выбор модели по номеру или ID. |
| `/tasks` | Список задач этого чата. |
| `/inspect …` | Чтение задачи по ID. |
| `/language …` | Установка языка, например `ru`. |
| `/pair …` | Применение одноразового кода сопряжения. |

`im.locale` задаёт язык по умолчанию. Пользователь может изменить его в боте. SQLite хранит состояние доставки между перезапусками. Сбой между доставкой и записью подтверждения может привести к дубликату.
